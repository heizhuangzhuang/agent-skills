# 贡献指南

感谢你帮助这套 Skill 变得更准确、更可执行。

## 可以贡献什么

- 微信小程序主体、类目、认证、备案、支付或能力边界的规则更新；
- 官方来源的新增、失效、跳转或语义变化；
- 静态审计器的新规则、误报修复和漏报样例；
- 原生、Taro、uni-app、云开发或自建后端的工程实践；
- 隐私、安全、UGC、性能、提审和拒审复盘模板；
- 能被自动验证的测试用例与最小复现项目。

## 证据标准

涉及平台规则或监管要求的 Pull Request，请优先提供一手来源：

1. 微信开放文档、腾讯客服、微信支付等平台官方页面；
2. 国家法律法规、国务院部门或地方主管机关官方页面；
3. 当前小程序管理后台的可复现路径。后台截图请先移除 AppID、姓名、手机号、身份证件和商户信息。

请同时说明：

- 核验日期与时区；
- 适用主体、类目、地区和功能；
- 原规则与新证据是否冲突；
- 结论是确定事实，还是仍需目标 AppID 实时核验。

转载、营销文章、无日期截图和搜索摘要可以作为检索线索，但不能单独作为规则依据。

## 本地验证

仓库只要求 Python 3.11+，核心脚本不依赖第三方包。

```bash
python3 -m compileall -q scripts
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/audit_miniprogram.py --list-rules
python3 scripts/check_official_sources.py --help
```

涉及在线来源变化时，再运行联网检查，并人工阅读发生变化的页面：

```bash
python3 scripts/check_official_sources.py \
  --registry references/source-registry.json
```

## 修改规则

- 每条静态规则必须有稳定 ID、严重度、触发证据、影响和可执行修复；
- 不要通过扩大正则范围换取表面召回率；必须增加命中与不命中的双向测试；
- 报告不得输出完整 Token、密码、手机号、身份证件或敏感查询参数；
- 无法静态确认的事实应降级为人工核验项，不要伪造确定结论；
- 不添加隐藏功能、审核后开关、套类目或支付绕行等审核对抗建议。

## 修改来源注册表

更新 `references/source-registry.json` 时：

- 使用稳定的官方 URL；
- 设置合适的 `authority`、`volatility`、`checked_at` 与 `use_for`；
- 页面需要登录、验证码或人工交互时使用人工检查模式；
- 页面变化只代表需要复核，不能让脚本自动重写规则结论；
- 同步更新相关参考文档和测试。

## Pull Request 检查清单

- [ ] 变更范围单一，提交信息能解释原因；
- [ ] 没有密钥、个人信息、私有 AppID 或管理后台敏感截图；
- [ ] 新增或修改行为有自动测试；
- [ ] 所有 27+ 项测试通过；
- [ ] README、Skill 工作流和参考资料没有互相矛盾；
- [ ] 动态规则附一手来源、核验日期和适用范围；
- [ ] 明确列出仍需实时后台核验的内容。

提交 Pull Request 即表示你同意按仓库的 [MIT License](./LICENSE) 授权你的贡献。
