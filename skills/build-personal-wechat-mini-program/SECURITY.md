# 安全政策

## 支持范围

安全修复优先进入默认分支的最新版本。仓库目前不维护并行的旧版本安全分支。

## 报告安全问题

请不要在公开 Issue 中披露以下内容：

- 能导致审计器绕过、敏感信息泄漏或命令执行的漏洞；
- 真实 AppID、AppSecret、支付密钥、云密钥、Cookie 或访问 Token；
- 用户个人信息、商户资料或未脱敏的管理后台截图；
- 尚未公开且可被直接利用的平台安全问题。

请通过 GitHub 的 [Private vulnerability reporting](https://github.com/juanyun-ai/build-personal-wechat-mini-program/security/advisories/new) 私下报告，并提供：

- 受影响文件与版本或 commit；
- 最小复现步骤；
- 实际影响和攻击前提；
- 建议修复方式（如有）；
- 是否已经向相关平台厂商报告。

维护者会尽快确认收到报告，在完成影响评估后协调修复与披露时间。请在修复公开前避免传播可直接利用的细节。

## 安全边界

本仓库的静态审计器用于发现工程风险线索，但不替代：

- 服务端渗透测试和依赖供应链审计；
- 微信小程序管理后台的能力、隐私和类目核验；
- 真机、弱网、权限、支付与内容安全测试；
- 法律、税务或行政许可意见。

一般规则错误、误报、漏报和官方页面更新可以提交公开 Issue；如果样例包含秘密或个人信息，请先构造脱敏的最小复现。
